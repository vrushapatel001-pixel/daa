Plagiarism Detection using String Matching Algorithms

DAA mini project, String Matching unit: the naive algorithm, Rabin–Karp and Knuth–Morris–Pratt. Paste a submission and a source, and the page marks the shared phrases and shows how much work each algorithm did.

Problem identification

Copied text is hard to spot by eye, especially in long documents. Teachers and editors need a fast, repeatable way to find passages that appear word for word in another text. This project finds them with string matching algorithms and compares how the algorithms perform.

InputsA submitted text S, a source text T, and k, the shortest phrase length in words (3 to 10).
OutputsThe overlap percentage of each text, both texts with shared phrases marked, a list of shared passages, and comparisons and time for each algorithm.
ConstraintsExact matches only, after lowercasing and removing punctuation. Reworded text is not detected. Everything runs in the browser, so very large inputs are slow.
ObjectivesFind every shared phrase of k or more words. Compare Naive, Rabin–Karp and KMP on comparisons and time. Check the measured results against the theoretical complexity.

Background study

Exact-match tools search for copied phrases directly. Fingerprinting tools such as MOSS hash many phrases and compare the hashes, which is where Rabin–Karp's rolling hash is used. Semantic tools find reworded text with language models. They go well beyond this syllabus unit, so they are out of scope.

Algorithm selection

The technique is String Matching (syllabus unit 7). Naive is the baseline. Rabin–Karp is chosen because hashing scales to many phrases. KMP is chosen because it guarantees linear time per search. Together they show the trade-off between simple, hashed and guaranteed approaches.

How the checker works

  1. Lowercase both texts and strip punctuation.
  2. Cut the submission into every run of k consecutive words.
  3. Search the source for each run with the chosen algorithm, matching at word boundaries.
  4. Mark every word covered by a match.
  5. Repeat with the texts swapped, then report both percentages.

    Work done on this input

    Every algorithm finds the same matches. They differ in character comparisons and time. Each one searched for every k-word phrase of the submission in the source.

    Method: each k-word phrase of the submission (the pattern, length m) is searched for in the source text (length n). Both texts are lowercased and stripped of punctuation first. Phrases are matched at word boundaries, so “cat” never matches inside “category”.

    Naive

    for i = 0 to n - m
  j = 0
  while j < m and T[i+j] = P[j]
    j = j + 1
  if j = m: report i

    Slides the pattern one position at a time and compares from the left.

    Knuth–Morris–Pratt

    lps = prefix table of P
j = 0
for i = 0 to n - 1
  while j > 0 and T[i] != P[j]
    j = lps[j-1]
  if T[i] = P[j]: j = j + 1
  if j = m: report i-m+1
     j = lps[j-1]

    Never moves backwards in T. After a mismatch the prefix table says how much of the pattern still matches.

    Rabin–Karp

    hp = hash(P); ht = hash(T[0..m-1])
for i = 0 to n - m
  if hp = ht and T[i..i+m-1] = P
    report i
  ht = roll(ht, T[i], T[i+m])

    Compares a number for each window and checks characters only when the hashes agree. A rolling hash updates in O(1).

    Complexity

    AlgorithmBest caseAverage caseWorst caseSpaceWorst-case input
    NaiveO(n)O(n)O(n·m)O(1)T = aaaa…a, P = aa…ab
    KMPO(n + m)O(n + m)O(n + m)O(m)None; always linear
    Rabin–KarpO(n + m)O(n + m)O(n·m)O(1)Every window hash collides

    For a submission of w words and k-word phrases, the checker runs about w − k + 1 searches. Total cost is that count times the cost per search. With KMP this is O(w·(n + m)).

    Step-by-step working

    Naive. Put the pattern at position 0 of the text and compare left to right. On the first mismatch, shift the pattern by one and start again. A full match is reported.

    KMP. First build the prefix table, which stores for each prefix of the pattern the length of its longest proper prefix that is also a suffix. Then scan the text once. On a mismatch, use the table to fall back inside the pattern instead of moving back in the text.

    Rabin–Karp. Hash the pattern and the first window of the text. At each position compare the two hashes. Only when they are equal, compare the characters to rule out a collision. Then slide the window by removing the old first character and adding the new last one.

    Why these three

    Naive is the baseline. KMP guarantees linear time per search. Rabin–Karp is the one used in practice by plagiarism tools, because hashing extends naturally to many patterns at once. Libraries: none. The project is plain JavaScript with no frameworks.
